02.1 · ShortcutRail module

精选分类 ShortcutRail

它不是品牌全量目录，而是帮助用户快速进入购物意图的一级入口。每个入口由一个稳定的 Product Type、一组候选商品和一张圆形缩略图组成。

Input 商品池

品牌页商品、名称、当前分类、可售状态、商品图和来源链接。

Decision 一级归类

按核心使用目的和护肤步骤归类；每个商品只有一个主分类。

Asset 7 张图

600×600 WebP，真实商品主体，适配圆形 full-bleed 裁切。

Output ShortcutRail

中英文名称、稳定顺序、目标链接和本地图片资源。

03.2 · End-to-end pipeline

从品牌页到可验收页面

红色节点代表必须保留的人工审核门。自动化负责收集、排序、生成和验证；涉及品牌判断、类目合并和包装真实性时不静默放行。

01

定义页面任务

输入品牌、目标语言、品牌页 URL、页面模板和目标分类数量。

  • 生成 GenerationBrief
  • 锁定来源和更新时间
02

采集商品池

读取品牌页与商品页，标准化名称、图片、可售状态和现有类目。

  • 去重 SKU / 变体
  • 记录来源与抓取时间
03

一级 Product Type

依据核心使用目的、商品形态和使用阶段，输出唯一主分类和可选标签。

  • 分类置信度
  • 冲突与未分类队列
04

审核分类与合并

确认名称、颗粒度、排序和中英文是否符合用户购物心智。

人工审核门 A
05

选择代表商品

按代表性、可售状态、缩略图识别度、热度和素材质量评分。

  • 每类 1–2 个主体
  • 保留候选与淘汰原因
06

生成分类图片

根据图片模式生成任务；统一构图、背景、裁切安全区和输出规格。

  • 提示词版本化
  • 输出资产 manifest
07

包装与视觉审核

检查商品身份、文字畸变、圆形裁切、相邻图片区分度和品牌一致性。

人工审核门 B
08

装配与 QA

写入 fixture / manifest，运行类型、测试、桌面端和移动端可视验证。

  • 报告成功 / 部分 / 阻塞
  • 保存生成证据

03.3 · Product selection

商品怎么选

分类图不是陈列尽可能多的商品，而是在 60–80px 的尺寸下传达一个清楚的购物入口。选品先保证“像这个分类”，再考虑热度。

1

代表性优先

商品名称、形态和使用场景能直接解释分类；不靠复杂文案才能看懂。

2

缩略图可识别

包装轮廓、主色和开合形态在圆形小图中仍明显；避免多个近似白瓶并排。

3

可售与素材稳定

优先当前可售、非临时组合、拥有清晰正面商品图的 SKU，并保留替补。

selection_score = 0.30 × category_fit + 0.25 × availability + 0.20 × thumbnail_legibility + 0.15 × popularity + 0.10 × asset_quality

默认权重，可按品牌策略配置。任何单项不合格都可触发人工否决，不由总分覆盖。

分类规模 图片主体数 默认策略 回退方式
1–2 个有效商品 1 选择最具代表性的单品，放大商品轮廓。 缺图则标记阻塞，不生成虚构商品。
3–8 个有效商品 1–2 主商品＋形态互补的次商品。 两个包装过于相似时退回单品。
9 个以上 2 用两种主要形态覆盖分类，不做商品墙。 按销量和素材质量选择替补。

03.4 · Image production

三种图片生成模式

目标生产模式是“真实商品抠图＋模板背景”，它能兼顾品牌准确性与批量一致性。参考图生成适合快速原型，但必须增加包装文字检查。

Fastest

A · 原商品图裁切

直接使用商品卡主图，统一尺寸和圆形裁切。速度最快、商品最真实，但背景和视觉语言不一致。

Production target

B · 抠图＋模板合成

保留真实包装像素，自动移除背景，再放入版本化的品牌场景模板。适合稳定批量生产。

Current prototype

C · 参考图生成

以商品图作为身份参考，让模型统一背景与构图。视觉自由度高，但可能改写包装细节。

任务：生成 {brand} 的 {category_zh} / {category_en} 分类缩略图。

身份约束：
- 只使用已选择的真实商品参考图：{selected_product_ids}
- 保持商品包装形状、主色、开合方式与品牌识别
- 不新增商品、Logo、标题、价格、折扣、评分或 UI

统一视觉：
- 1:1 正方形，适配圆形 full-bleed 裁切
- 商品位于中心安全区，主体 1–2 个
- 浅色韩系棚拍，柔和自然阴影
- 使用 {category_visual_cue} 表达分类，不遮挡包装

输出：
- 600 × 600 WebP
- 文件名：category-{category_slug}.webp
- 记录 prompt_version、source_images、output_hash

04.1 · Full-page assembly

整页模块装配

整页自动化不是一次生成一段 HTML，而是由同一份 PageGenerationSpec 驱动各模块，再复用现有设计系统组件装配 TopicLandingPage。

ThemeHero

品牌认知与主张

  • 从品牌资料生成一句定位、简短说明和 2–3 个标签。
  • 选择 2–3 个跨品类主商品；主图以真实包装合成为生产目标。
  • 检查文案证据、品牌发音 / 中文名、CTA 目标和移动端可读性。
输入brand_profile + hero_candidates + locale
输出ThemeHeroProps + hero-image.webp

ShortcutRail

一级购物入口

  • 执行本页定义的分类、选品和图片流程。
  • 输出 5–8 个稳定分类；超过容量则按覆盖率和购物价值压缩。
  • 保证中英文映射、顺序、链接和图片 manifest 一一对应。
输入product_pool + taxonomy_rules
输出ShortcutRailProps + category-*.webp

ThemeProductList

按护肤任务开始

  • 从用户任务而非商品类目生成 3–5 个场景，如清洁焕新、修护焕肤。
  • 每个场景选择一张情境图和 3–4 个可购买商品。
  • 避免与“精选分类”完全重复，强调解决问题的顺序。
输入brand_routines + selected_products
输出ThemeProductListProps

Product rail

高价值商品精选

  • 在可售商品中结合销量、评分、折扣和品类覆盖进行排序。
  • 保留“全量”与高价值子类标签，避免每个标签商品相同。
  • 价格和库存属于易变数据，生成前必须刷新。
输入live_catalog + merchandising_rules
输出ProductListProps

ReviewList

可追溯的用户证据

  • 仅使用真实评论与对应商品，保存评论来源和抓取时间。
  • 按清洁、调理、护理等不同体验选取 3 条，不改写为广告语。
  • 缺少可靠评论时明确阻塞，不自动编造。
输入verified_reviews
输出ReviewListProps

ProductList waterfall

全量发现与承接

  • 展示当前品牌可售商品并生成真实筛选标签。
  • 分页、加载更多和排序由商品数据驱动，不写死数量。
  • 验证首屏性能、图片加载、无重复商品和空状态。
输入live_catalog + filter_schema
输出ProductListProps

04.3 · QA & roadmap

验收标准与演进顺序

自动化只有在数据、资产、运行时和视觉四层证据都通过后才算完成。任何人工审核门未通过，状态只能是部分完成或阻塞。

01
分类完整性

所有有效商品有唯一一级分类；未分类和冲突商品显式列出。

02
双语一致性

分类 ID 稳定，中英文仅是 label，不产生两套排序或链接。

03
商品真实性

名称、图片、价格、库存和评论均可回溯到来源与时间。

04
资产规范

图片存在、尺寸正确、可加载、无 UI 残留，包装未被错误重绘。

05
运行时验证

类型检查和 Storybook 测试通过，数量断言不写死在共享组件。

06
视觉验证

桌面端和移动端检查裁切、标签换行、横向滚动和相邻图片区分度。

Current v0.1

固化当前分类模块的规则、数据契约、提示词和验收门。

  • 人工采集商品
  • 人工审核分类与图片
  • 代码接入与 Storybook QA
Next v0.2

增加 manifest 生成器和资产任务队列，让分类模块可重复运行。

  • 商品 JSON 导入
  • 规则化分类与评分
  • 自动生成 fixtures patch
Later v0.3–1.0

接入实时目录，依次生成 Hero、场景导购、商品精选、评论和全量列表。

  • 模块级审核与重跑
  • 差异报告和回滚
  • 整页一键装配，人工批准发布

下一步不是“让模型再生成一次”，而是把每次判断沉淀为规则、版本和证据，让下一次生成更少依赖临时记忆。
