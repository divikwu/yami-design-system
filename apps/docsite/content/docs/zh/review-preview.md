共享预览的目标是让同事看到与你相同的一版页面，并能复现你要讨论的问题。仓库链接、截图和本机地址都不能单独完成这件事。

本页负责“怎样邀请别人评审”。页面本身需要检查哪些内容，统一使用[页面检查清单](/zh/docs/review-checklist)。

## 开始前

- 已保存可恢复的任务版本，并说明仍未提交或未导出的内容。
- 已完成一次自检，能说明希望评审者回答的问题。
- 发布负责人已确认可用的预览环境、允许访问的人和素材范围。

仓库私密不代表预览网站私密。首次共享前，用预期评审者的账号确认能打开，并按环境要求核对未授权访问是否被阻止。

如果还没有授权的预览环境，不要把新建服务或公开部署当作默认步骤。先申请环境；等待期间可屏幕共享或安排对方本地复现，并明确记录共享限制。

## 固定评审版本

正式数据型页面评审默认使用固定的 Snapshot，而不是会继续变化的 Live 结果。记录快照标识或文件路径及摘要，使代码和数据能够一起还原。

1. 选定本轮代码 SHA，导出仍在浏览器里的必要草稿。
2. 固定商品、价格、分类和文案来源；已接入数据模式的页面选择 Snapshot。
3. 空、加载、错误等补充状态使用指定 Scenario，并记录名称和配置。
4. 尚未接入 Snapshot 的页面，先由协作者保存可复现的数据文件；不要把随时变化的接口结果标作快照。
5. 纯静态页面注明内容文件与代码一起固定，没有实时商品请求。
6. 记录语言、主题、Viewport 和操作起点，再生成或更新已授权的预览。

Live 可以单独用于观察数据变化和运行异常，但不能作为两版设计唯一的比较基准。资料未固定时，先做探索讨论，不宣称已完成可复现的正式对比。

## 发出评审邀请

把以下记录与可点击预览放在一起，不只发送 Storybook 首页：

```text
任务 / 制作者 / 评审者：
本轮需要确认的问题：
预览地址 / 具体 Story 或页面路径：
访问方式与有效期：
Fork / 分支 / 代码 SHA：
Snapshot 标识或路径与摘要 / 补充 Scenario：
语言 / 主题 / Viewport：
操作起点与步骤：
已完成的自检 / 已知问题：
希望反馈的时间：
```

Viewport 写具体宽度，例如 `375px` 或 `1440px`，不要只写“手机”和“电脑”。若 URL 未保留工具栏状态，请在记录中说明如何切换。

预览地址不要包含凭证。需要登录时，说明使用哪个已授权账号体系，不在评审记录里共享密码。

## 记录反馈并复查

1. 评审者先确认页面版本和数据，与邀请记录一致后再检查。
2. 按[统一清单](/zh/docs/review-checklist)检查，并围绕本轮问题提出反馈。
3. 每个问题写明位置、操作、实际结果、预期结果和优先级；截图只作辅助。
4. 制作者确认本轮处理哪些问题，再让 AI 修改，不把所有建议自动视为已批准需求。
5. 修改后记录新 SHA，更新预览和变化说明，请评审者复查对应问题。
6. 记录谁在什么版本上确认通过，以及哪些问题明确延期。

评审期间更新同一个预览地址时，必须通知参与者版本已变化。否则两条反馈可能对应不同页面。

## 你应该看到什么

评审者能独立打开指定入口，看到约定的内容与状态，并重现问题。通过或不通过的结论指向明确 SHA 和数据版本。

“截图看过”“本地能打开”和“团队预览通过”是不同结果。记录实际完成的验证，不用模糊的“已完成”代替。

## 遇到问题时

- **别人打不开 localhost**：它指向对方自己的电脑；换用授权共享预览，或约定本地复现。
- **打开后内容不一样**：先核对 SHA、数据、语言和缓存，再判断是否实现问题。
- **访问要求与保密范围冲突**：停止扩大分享，请环境负责人处理，不擅自取消访问控制。
- **同一问题反复出现**：补充稳定操作步骤和最小示例，再交给 AI 或组件维护者。
