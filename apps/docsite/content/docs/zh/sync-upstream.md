上游合入一个组件改进，不会自动更新你的 Fork、正在制作的页面或已部署预览。你需要选择同步时机，接收更新，再检查自己的页面是否仍然正确。

同步分两段：先更新保持干净的 Fork `main`，再把确认过的更新带入任务分支。不要通过把业务分支合回 main 来“消除差异”。

## 开始前

确认这些信息后再同步：

- 上游发布或合并说明中，哪些改动与你的页面有关。
- 本次要接收的上游 SHA，而不只是含糊的“最新代码”。
- 当前任务已保存的检查点 SHA，以及尚未提交或导出的内容。
- 正在评审或交付的页面是否需要保持不变；如需保持，另开同步验证分支。

先让协作者执行只读检查：

```bash
git status --short --branch
git remote -v
git rev-parse HEAD
```

有未确认的改动时，先记录归属并安全保存。不要把强制覆盖、`reset --hard` 或整仓暂存当作同步准备。

## 更新 Fork 的基线

1. 核对 `upstream` 是团队主项目，`origin` 是自己的 Fork。
2. 在 GitHub 打开自己的 Fork，切到同步用的 `main`，查看上游差异。
3. 确认其中没有自己的业务提交，并且上游分支头仍等于本次批准的 SHA，再使用 **Sync fork → Update branch** 接收更新。这个按钮跟随上游分支头，不用于锁定某个历史版本；如果上游已经前进，交由协作者按批准的 SHA 操作，不点击同步。
4. 若提示冲突、分叉或会丢弃提交，停止，让协作者解释差异，不选择强制同步。
5. 远程更新后，再让协作者获取更新，并在工作目录干净时快进本地 main。
6. 记录接收后的 SHA，与本次确定的上游版本核对。

GitHub 的同步入口更新远程 Fork；本地仍需要获取更新。命令行操作也要区分本地与远程，不能只凭其中一处显示最新就宣布全部完成。参见 [GitHub 同步 Fork 指南](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/syncing-a-fork)。

main 出现独有提交时，需要先判断是否混入业务工作。保留这些提交后由协作者提出处理方案，不为了保持“干净”删除它们。

## 把更新带入任务

这一步才会影响正在制作的页面。请明确授权协作者合入哪次上游更新：

```text
请先检查我的任务分支、工作目录和未提交改动。
任务版本：<任务分支与检查点 SHA>
接收版本：<已确认的上游 SHA>
请先说明影响范围和保留方案，再在独立同步验证分支合入更新。
遇到冲突暂停并列出文件，不强推、不硬重置、不覆盖他人工作。
用原评审数据检查页面，报告改动和验证结果。
未经另行授权，不推送、不合并其他分支、不部署。
```

替换占位内容后再使用。不要让 AI 同时升级组件、重写业务页面和修改视觉方向；这样很难判断变化来自哪里。

## 处理冲突

1. 让协作者列出冲突文件、双方改动目的和影响的页面。
2. 内容冲突由业务负责人确认；公共契约冲突请组件维护者参与。
3. 对每处冲突决定保留或组合什么，不整批接受“我的版本”或“他们的版本”。
4. 生成文件冲突先解决源文件，再按仓库命令重新生成并检查差异。
5. 冲突解决后复查完整改动，并重新运行相关检查。

如果无法判断，保留原任务检查点和同步验证分支，暂停升级。Git 认为没有冲突也不代表语义或视觉没有变化。

## 验证并记录结果

使用同步前同一份 Snapshot、语言、主题和视口，对照[页面检查清单](/zh/docs/review-checklist)。请协作者按变更范围运行仓库检查，并说明哪些没有运行。

记录同步前后任务 SHA、上游 SHA、受影响页面、已处理冲突和剩余问题。验证通过后再决定是否把同步结果用于原任务或发布。

预期结果是：公共更新已进入指定任务，业务内容被保留，页面仍能完成原来的用户任务。若预览还没更新，清楚注明它仍展示旧版本。

## 遇到问题时

- **Fork 显示已同步，页面没变**：检查本地任务分支和预览部署是否仍是旧版本。
- **同步后测试失败**：保留失败证据，区分公共改动与本地适配问题，不跳过检查直接发布。
- **评审中的页面突然变化**：恢复使用已记录的评审入口或检查点，并另安排同步验证；不要改写共享历史。
- **只有一个公共修复急需接收**：先请维护者判断依赖，不擅自复制几个文件替代完整同步。

## 下一步

同步结果需要同事确认时，重新[共享预览与评审](/zh/docs/review-preview)。发现可通用的修复时，走[选择性贡献上游](/zh/docs/contribute-upstream)。
